# CLAUDE.md

«Быки и коровы», облегчённая версия: Telegram Mini App + сервер. Требования — [docs/requirements.md](docs/requirements.md), правила — [docs/rules.md](docs/rules.md), решения и устройство — [docs/decisions.md](docs/decisions.md).

## Роли

- Автор — QA-инженер, TypeScript и фронтенд для него новые. Он принимает решения и тестирует руками (UX и бизнес-логика).
- Агент пишет код и все автотесты.
- Объяснения — подробно и простыми словами, но только в чате.

## Только с подтверждения автора

Коммит, push, слияние, удаление веток, деплой, любые действия на сервере, глобальные установки. Секреты (`.env`, токены, пароли) не выводить.

Согласованные документы (`docs/requirements.md`, `docs/rules.md`, принятые решения в `docs/decisions.md`) меняются только после обсуждения с автором.

## Как работаем

- Этапы — [docs/decisions.md](docs/decisions.md). На этап — ветка `stage-N-<name>`, один PR, тег версии.
- Поведение, которого нет в макете Mini App первой версии, — сначала показать автору.
- Перед словом «готово» — `pnpm check` (формат, линтер, типы, тесты) проходит целиком.
- Изменение только в `.md` — без `pnpm check`, и CI его не запускает: ни одна проверка не читает документы. Подтверждение коммита и push — как обычно.
- Решение принято — строка в `docs/decisions.md`. Новый запрос к базе — строка в «Цена запросов».
- Конец этапа — запись в «Итоги этапов» (`docs/decisions.md`): что сделано, ошибки агента, правки автора, уроки. Коротко и честно.
- Документация — на русском и коротко. Имена в коде и коммиты (Conventional Commits) — на английском.
- Комментарии в коде — только о неочевидном «почему».
- Инструкции автору — под маленькое окно терминала: важное — последним.

## Сервер

Доступа у агента нет. Агент готовит пошаговую инструкцию, её выполняет сессия Claude Code на ВМ; каждое изменяющее действие подтверждает автор. rpg_tele_bot на той же ВМ не трогать. Один токен бота — один получатель обновлений: предупредить, когда нужно остановить бота первой версии.

## Команды

```
pnpm install     зависимости
pnpm db:up       PostgreSQL для разработки (нужен .env по образцу .env.example)
pnpm check       всё, что проверяет CI
pnpm test:watch  тесты при сохранении
```
