# Журнал решений

Короткие записи: что решили и почему. Решение меняется — добавляется новая строка, старая остаётся. Сравнение — с первой версией (v1).

## Устройство

```
Mini App (React) ──HTTPS──► Caddy ──► сервер (Node, Fastify) ──► PostgreSQL
                            └─ отдаёт собранные файлы Mini App
```

```
src/domain/   правила: чистые функции, без импортов
src/server/   приём запроса → сценарий (транзакция, запросы Kysely) → domain
src/web/      Mini App: экраны, логика клеток ввода
src/shared/   типы ответов API и коды ошибок — общие для сервера и браузера
locales/      ru/*.ftl, en/*.ftl
```

Границы проверяет ESLint (`no-restricted-imports`), а `tests/architecture.test.ts` — что правила действительно срабатывают:

| Папка | Не может импортировать |
|---|---|
| `domain` | ничего, кроме своих файлов |
| `shared` | `domain`, `server`, `web` |
| `server` | `web` |
| `web` | `domain`, `server` |

## Решения

Все — решения автора, 2026-10-14.

| Тема | Решение | Почему | Вместо (v1) |
|---|---|---|---|
| Клиенты | Только Mini App | Один клиент — нет переноса партии между клиентами и служебного входа | Бот + Mini App |
| Бот | Описание бота + ответ на `/start` с кнопкой «Играть»; webhook в том же сервере. Старые кнопки v1 не обрабатываем | Без ответа `/start` выглядит сломанным; webhook не держит long polling | Полноценный бот, 4500 строк |
| Репозиторий | Один пакет, папки | Общий код сервера и браузера — несколько типов | Монорепозиторий из 3 пакетов |
| Сервер | Fastify, zod для входящих запросов, pino | Знакомо по v1, быстро | То же |
| Вход | Своя проверка `initData` на `node:crypto` | Граница безопасности — каждая строка на виду | То же |
| База | **Kysely** — построитель запросов | Запросы — TypeScript, имена проверяет компилятор, выполняется ровно написанное | Prisma: 18% процессора, `_count` считал ходы всей базы |
| Миграции | Встроенный Migrator Kysely, при старте сервера; только вперёд | Идёт с Kysely; Alembic — это Python | Prisma Migrate |
| Проверка SQL | `pg_stat_statements` и `EXPLAIN` на нагрузочном замере | Любой инструмент может удивить | То же, после инцидента |
| Клиент | React + Vite, Fluent; оформление — как в v1 | Перенос дизайна, честное сравнение | То же |
| Аналитика | Нет журнала событий; файл SQL-запросов к партиям и ходам | Смотреть некому; история с временем ходов уже есть | События, представления, Grafana |
| Ошибки браузера | В лог сервера, не больше 5 с одной страницы | Разбирает один человек | Таблица ошибок с очисткой |
| Рейтинг | Сводка в `players` сразу, пересчёт в транзакции конца партии; механизма пересчёта при смене формулы нет | Формула не меняется; без сводки v1 падал при 10 000 игроков | Сводка + автоматическая пересборка |
| API | Без версии в адресе, без Swagger | Клиент и сервер выпускаются вместе | `/v1`, OpenAPI |
| Тесты | Правила — примеры и свойства, 100%; сервер — на настоящей базе; клиент — основные пути; 3 сквозных (Chromium, WebKit); 1 нагрузочный замер локально | Тесты по цене ошибки | + мутационное, фаззинг, тесты по модели |
| Выпуск | Сразу на сервере вместо v1, переключение на этапе 3; данные v1 удаляются | Играет только автор — простоев не боимся | — |
| Процесс | Приватный репозиторий; ветка, PR и тег на этап | — | — |
| CI для документов | Изменение только в `.md` — без `pnpm check` и без CI | Ни одна проверка не читает документы | То же |

## Цена запросов

Как растёт цена с объёмом данных. Заполняется по мере появления запросов.

| Запрос | Цена | При 10 000 игроков |
|---|---|---|
| Открыть Mini App | поиск игрока по индексу + последняя партия с ходами | не зависит от базы |
| Ход | блокировка строки партии, вставка хода; «осталось вариантов» — P(10, L) × число ходов на процессоре | не зависит |
| Конец партии | последние 20 партий игрока по индексу, обновление сводки | не зависит |
| Своя статистика | все партии одного игрока | растёт с историей игрока |
| Топ-10 | первые строки индекса сводки | не зависит |
| Моё место | число игроков выше по индексу сводки | до 10 000 строк индекса, ~1–2 мс; пересмотреть при ~100 000 |

**Граница длины числа:** P(10, 4) = 5 040, P(10, 6) = 151 200 (~30 мс на ход); при L ≥ 7 подсчёт «осталось вариантов» нужен другой.
