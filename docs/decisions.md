# Журнал решений

Короткие записи: что решили и почему. Решение меняется — добавляется новая строка, старая остаётся. Сравнение — с первой версией (v1).

## Устройство

```
Mini App (React) ──HTTPS──► Caddy ──► сервер (Node, Fastify) ──► PostgreSQL
                            └─ отдаёт собранные файлы Mini App
```

```
src/domain/   правила: чистые функции, без импортов
src/server/   приём запроса → сценарий (транзакция, запросы Kysely) → domain
src/web/      Mini App: экраны, логика клеток ввода
src/shared/   типы ответов API и коды ошибок — общие для сервера и браузера
locales/      ru/*.ftl, en/*.ftl
```

Границы проверяет ESLint (`no-restricted-imports`), а `tests/architecture.test.ts` — что правила действительно срабатывают:

| Папка | Не может импортировать |
|---|---|
| `domain` | ничего, кроме своих файлов |
| `shared` | `domain`, `server`, `web` |
| `server` | `web` |
| `web` | `domain`, `server` |

## Решения

Все — решения автора, 2026-10-14.

| Тема | Решение | Почему | Вместо (v1) |
|---|---|---|---|
| Клиенты | Только Mini App | Один клиент — нет переноса партии между клиентами и служебного входа | Бот + Mini App |
| Бот | Описание бота + ответ на `/start` с кнопкой «Играть»; webhook в том же сервере. Старые кнопки v1 не обрабатываем | Без ответа `/start` выглядит сломанным; webhook не держит long polling | Полноценный бот, 4500 строк |
| Бот и язык (2026-10-15) | Приветствие отправляется запросом к Telegram и запоминается (`bot_greetings`); смена языка в Mini App переписывает его и надпись кнопки меню в этом чате; новый `/start` удаляет прежнее приветствие (если новое ушло и прежнему меньше 48 часов). Отказы Telegram — в лог, смене языка не мешают | После смены языка в Mini App приветствие в чате оставалось на старом языке до нового `/start` (нашёл автор) | Ответ внутри webhook — номер сообщения не узнать |
| Репозиторий | Один пакет, папки | Общий код сервера и браузера — несколько типов | Монорепозиторий из 3 пакетов |
| Сервер | Fastify, zod для входящих запросов, pino | Знакомо по v1, быстро | То же |
| Вход | Своя проверка `initData` на `node:crypto` | Граница безопасности — каждая строка на виду | То же |
| База | **Kysely** — построитель запросов | Запросы — TypeScript, имена проверяет компилятор, выполняется ровно написанное | Prisma: 18% процессора, `_count` считал ходы всей базы |
| Миграции | Встроенный Migrator Kysely, при старте сервера; только вперёд | Идёт с Kysely; Alembic — это Python | Prisma Migrate |
| Проверка SQL | `pg_stat_statements` и `EXPLAIN` на нагрузочном замере | Любой инструмент может удивить | То же, после инцидента |
| Клиент | React + Vite, Fluent; оформление — как в v1 | Перенос дизайна, честное сравнение | То же |
| Аналитика | Нет журнала событий; файл SQL-запросов к партиям и ходам | Смотреть некому; история с временем ходов уже есть | События, представления, Grafana |
| Ошибки браузера | В лог сервера, не больше 5 с одной страницы | Разбирает один человек | Таблица ошибок с очисткой |
| Рейтинг | Сводка в `players` сразу, пересчёт в транзакции конца партии; механизма пересчёта при смене формулы нет | Формула не меняется; без сводки v1 падал при 10 000 игроков | Сводка + автоматическая пересборка |
| API | Без версии в адресе, без Swagger | Клиент и сервер выпускаются вместе | `/v1`, OpenAPI |
| Тесты | Правила — примеры и свойства, 100%; сервер — на настоящей базе; клиент — основные пути; 3 сквозных (Chromium, WebKit); 1 нагрузочный замер локально | Тесты по цене ошибки | + мутационное, фаззинг, тесты по модели |
| Выпуск | Сразу на сервере вместо v1, переключение на этапе 3; данные v1 удаляются | Играет только автор — простоев не боимся | — |
| Процесс | Приватный репозиторий; ветка, PR и тег на этап | — | — |
| CI для документов | Изменение только в `.md` — без `pnpm check` и без CI | Ни одна проверка не читает документы | То же |

## Цена запросов

Как растёт цена с объёмом данных. Заполняется по мере появления запросов.

| Запрос | Цена | При 10 000 игроков |
|---|---|---|
| Открыть Mini App | вставка или обновление игрока по уникальному индексу + последняя партия с ходами | не зависит от базы |
| Любой запрос после входа | поиск игрока по `telegram_id` (уникальный индекс) | не зависит |
| Ход | блокировка строки партии, вставка хода; «осталось вариантов» — P(10, L) × число ходов на процессоре | не зависит |
| Конец партии | статус и число ходов всех законченных партий игрока (без ходов), обновление сводки | растёт с историей игрока, не с базой |
| Своя статистика | то же + место по индексу сводки | растёт с историей игрока |
| Топ-10 | первые строки индекса сводки (0,08 мс при 10 000 игроков; см. [load.md](load.md)) | не зависит |
| Моё место | число игроков выше по индексу сводки | растёт с местом игрока; 0,5 мс при 10 000; пересмотреть при ~100 000 |

**Граница длины числа:** P(10, 4) = 5 040, P(10, 6) = 151 200 (~30 мс на ход); при L ≥ 7 подсчёт «осталось вариантов» нужен другой.

## Итоги этапов

### Этап 0 — фундамент (v0.1.0, 2026-10-14)

**Сделано.** Проектирование в чате. Каркас: `pnpm check` (Prettier, ESLint, tsc, Vitest), правила границ модулей и тест, что они срабатывают, PostgreSQL в Docker, CI. Требования, правила, журнал решений, `CLAUDE.md`.

**Правки автора.**
- Приветствие в боте нужно — без него `/start` выглядит сломанным.
- Аналитику свели к SQL-запросам по партиям и ходам, без журнала событий.
- SQL не должен лежать строками в коде — выбрали Kysely вместо SQL вручную.
- Не нужен туннель и вторая Mini App для проверки на телефоне — сразу на сервере вместо первой версии, её данные не храним.
- Изменения только в `.md` — без тестов и CI.
- Из обновлённых принципов взяли не всё (см. «Обновление принципов»).

**Ошибки агента** (все найдены до коммита).
- Ссылка из требований на папку первой версии по относительному пути: на GitHub она бы не открылась.
- `CLAUDE.md` ссылался на раздел «Этапы», которого ещё не было.
- Результат CI ждал двумя способами одновременно — лишняя работа.

**Уроки.**
- «Облегчённая» не значит «самая короткая»: SQL строками в коде — меньше кода, но автору важнее читаемость. Спрашивать, что автор ценит, а не только что меньше.
- Простейший путь проверки иногда даёт ограничение, о котором агент не знает: играет только автор, поэтому простой на сервере ничего не стоит.

### Этап 1 — правила (2026-10-14)

**Сделано.** `src/domain`: проверка хода, подсчёт быков и коров, генерация числа, «осталось вариантов», состояния партии, статистика и рейтинг. 95 тестов: примеры из [rules.md](rules.md), граничные случаи, свойства (fast-check). Покрытие 100%. Восемь нарочных поломок правил — все пойманы тестами.

**Решения по ходу.**
- Отказ — не исключение, а результат с кодом (`{ ok: false, error }`): сервер обязан разобрать каждый код, это проверяет компилятор. Исключение — только для ошибки программиста (длина вне 1–10).
- Случайность приходит параметром (`randomInt`): сервер передаст `crypto.randomInt`, тесты — заданную последовательность.
- Список всех чисел длины строится один раз и запоминается: «осталось вариантов» считается на каждом ходе.
- Личное «среднее» считается той же функцией, что и рейтинг, — расхождение невозможно.

**Ошибки агента.**
- Правило границ этапа 0 запрещало пакеты всем файлам `src/domain`, в том числе тестам. Тест границ этого не ловил: в нём не было случая с файлом теста. Исправлено, случай добавлен.
- Два свойства были записаны как `(…) => expect(…)`. fast-check принял ложное возвращаемое значение за провал. Тесты упали, а не прошли молча; переписаны.
- Одна команда правки файла собрана с ошибкой (незакрытый heredoc). Сработал запасной путь, результат проверен.

### Этап 2 — сервер (2026-10-14)

**Сделано.** Сервер на Fastify и Kysely по [api.md](api.md): вход по подписи Telegram, все запросы, ограничение частоты, одна точка обработки ошибок, миграция с ограничениями в базе, строка в логе о медленных ответах со счётчиком запросов к базе. Тесты: подпись (в том числе против хэша, посчитанного по документации Telegram независимо), сценарии на настоящей базе, одновременные запросы, сводка рейтинга против правил на случайных историях. Каждый ответ в тестах проверяется: у идущей партии нет загаданного числа. 10 нарочных поломок — все пойманы; две поломки одного из двух замков против двойного хода выжили, как и должны.

**Решения по ходу.**
- Ручная проверка сервера командами — избыточна: сервер проверяется руками через Mini App на этапе 3 (решение автора).
- Двойной ход останавливают два замка: блокировка строки партии и первичный ключ хода. Нарушение ключа отвечает `409`, а не `500`.
- Тело не в JSON сервер не читает, а не отклоняет: PowerShell шлёт пустой POST с типом формы.
- Тесты на базе идут в отдельной базе `bulls_test` по одному файлу; быстрые — параллельно.

**Ошибки агента.**
- Команды PowerShell для ручной проверки сначала не работали: пустой POST получал `request.invalid`. Найдено при пробном прогоне команд до передачи автору.
- Самодельный тип строки таблицы вместо готового `Selectable` из Kysely; исправлено до коммита.
- Ещё одна команда с поломанным экранированием кавычек; список поломок вынесен в скрипт.

### Этап 3 — Mini App, бот, сервер (2026-10-14)

**Сделано.** Mini App: заглавный экран, игра, подтверждение, итог с анимацией победы, сбои (нет связи, вход устарел, открыто не из Telegram, ошибка страницы → лог сервера). Тексты — `locales/ru.ftl`, `locales/en.ftl`, общие для Mini App и бота. Бот: webhook в сервере, ответ на `/start` — в ответе на сам webhook; `pnpm bot:setup`. Образы, Caddy, Compose для ВМ, отдельный пользователь базы без прав администратора; весь рабочий стек поднят и проверен локально. Инструкция для ВМ — [deploy.md](deploy.md). Тесты: логика клеток, экраны с подменённым сервером, тексты, бот, сборка без кода подписи, сквозные в Chromium и WebKit с проверкой доступности (axe). 11 нарочных поломок Mini App — 10 пойманы сразу, для 11-й (подпись кнопки «Стереть») добавлен тест.

**Решения по ходу.**
- Один файл текстов на язык; приставки `webapp-` больше не нужны — клиент один.
- Ответ бота возвращается в ответе на webhook: сервер сам в Telegram не ходит.
- У страницы есть язык (`lang`) — VoiceOver читает с верным произношением. Нашёл axe.
- Контраст по WCAG AA (решение автора): главная кнопка `#8f7a66` → `#84705e`, серый текст — свой `#797572` вместо цвета подсказок Telegram (у того в светлой теме бывает 2,85:1).
- Масштабирование пальцами разрешено (решение автора); двойное касание по-прежнему не увеличивает (`touch-action: manipulation`).
- Переключение на сервере прошло; игра работает на телефоне. Проверка VoiceOver и «уменьшить движение» перенесена в ручную проверку этапа 4 (решение автора).
- IP ВМ меняется при перезапуске, обновления адреса в DuckDNS нет. Обновление (cron) — на этапе 5 (решение автора). **Риск до этого:** после перезапуска ВМ адрес указывает на старый IP, и Mini App не открывается — обновить адрес в DuckDNS вручную.

**Ошибки агента.**
- Прокси Vite пересылал на сервер всё, что начинается с `/api`, включая файл кода `/api.ts`: страница была пустой. Найдено при первом открытии.
- Тест сборки сначала собирал отладочную версию (Vitest задаёт `NODE_ENV=test`) и падал на чистом коде. Исправлено; чувствительность проверена нарочной утечкой.
- Шаблон числа в сквозном тесте не учёл пробел между разрядами («1 260»).
- Сквозной тест читал загаданное число до того, как партия создана: падал в WebKit. Теперь ждёт экран игры.
- Два раза создавал корень React на одном элементе; `execute` вызывал сам себя — поймал линтер хуков.

### Этап 4 — статистика, рейтинг, язык, замер (2026-10-14)

**Сделано.** Экран статистики и рейтинга, кнопка языка (выбор — на сервере, бот отвечает на нём же). Тесты экрана и склонений; третий сквозной тест (статистика и язык) с проверкой доступности. Нагрузочный замер одной командой — [load.md](load.md).

**Решения по ходу.**
- Темп игрока в замере — 10–20 с на ход: так играет человек (решение автора).
- Требование «95% ходов быстрее 500 мс» при 1000 игроках не выполнено: медиана 19 мс, но волны ходов упираются в один процесс сервера. Оставляем один процесс до реальной нагрузки; сигнал и план пересмотра — в [load.md](load.md) (решение автора). Первая версия упёрлась в то же.
- Серый текст — `#6b6865` в светлой теме, `#93a5b8` в тёмной: подписи плиток статистики не проходили контраст на фоне плитки (решение автора).
- Английские порядковые числа (1st, 22nd, 111th) — по правилам языка: число помечается как порядковое в коде.

**Находка ручной проверки (автор).** Смена языка в Mini App не меняла приветствие в чате до нового `/start`. Теперь приветствие и кнопка меню переписываются сразу; описание бота в пустом чате зависит от языка приложения Telegram — его бот не меняет.

**Находки замера, исправлены.** Индекс рейтинга не использовался (миграция `0002`); подсчёт вариантов в 2–3 раза быстрее; ключ подписи считается один раз.

**Ошибки агента.**
- На этапе 3 влил PR, пока шёл CI последнего коммита (только документы, код уже был проверен). Результат — зелёный, но порядок нарушен.
- Серый `#797572` на этапе 3 проверял только на белом фоне, а на плитках статистики он не проходил — нашёл axe.
- Частичный индекс рейтинга (этап 2): в «Цене запросов» записал «не зависит», не проверив план запроса. Нашёл замер.
- Скрипт замера сначала ждал k6 синхронно — процессор и память не снимались.
- Замер процессора на запрос внутри одного процесса оказался шумным (3,6 и 5,3 мс на одном коде) — выводы делаю только по полным прогонам.
- Несколько команд с поломанным экранированием и одна заплатка, не нашедшая строку после Prettier — правки сделаны напрямую.
